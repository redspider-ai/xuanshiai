# 微信支付 APIv3 接入契约

> 版本：2026-10-30
> 适用范围：用户端会员/爆灯/置顶/红娘服务单/活动/虚拟商品支付、后台退款与对账
> 代码基线：`app/services/payment/`、`app/workers/payment_worker.py`、`app/workers/reconcile_worker.py`
>
> 旧的 `/payments/test/pay`、`/payments/wechat/callback` 仅保留给 development/testing，见文末「旧测试支付」。

---

## 一、通用约定

### 1.1 金额与状态

- 数据库金额统一 `decimal(12,2)` 元。
- 调微信 APIv3 时统一转换为整数「分」：`amount_cents = int(Decimal(amount) * 100)`。
- 支付订单状态（`payment_order.status`）：

| 值 | 含义 |
|---:|---|
| 0 | 待支付 |
| 1 | 支付成功 |
| 2 | 支付失败/关闭 |
| 3 | 已全额退款 |

- 履约状态（`payment_order.fulfillment_status`）：`PENDING/PROCESSING/SUCCESS/FAILED/DEAD`
- 退款状态（`payment_refund.status`）：`CREATED/PROCESSING/SUCCESS/FAILED/CLOSED`
- 退款汇总（`payment_order.refund_status`）：`NONE/PARTIAL/FULL`

### 1.2 认证与权限

- 用户端接口：`Authorization: Bearer <access_token>`。
- 后台接口：红娘后台 access token，且必须具备对应权限码。
- 敏感后台操作：`Idempotency-Key`（8-128）+ `confirm=true`。
- 微信回调：不登录，必须通过 APIv3 平台证书/公钥验签。

### 1.3 安全边界

- 回调验签使用 `Wechatpay-Timestamp/Nonce/Signature/Serial`，时间戳默认容差 300 秒。
- 回调 `resource` 使用 APIv3 密钥 AES-256-GCM 解密，不落原始密文。
- 支付/退款回调均以 `notify_id` 写入 `payment_notify_log` 唯一键防重放。
- 金额、商户号、AppID、交易状态、币种必须逐项校验。
- 私钥/APIv3 密钥只从环境变量或 KMS 读取，禁止写入数据库配置或前端。

## 二、环境变量配置

| 变量 | 必填 | 说明 |
|---|---|---|
| `WECHAT_PAY_MODE` | 是 | `disabled`（默认，不启用新网关）/ `mock`（仅本地）/ `real`（真实支付） |
| `WECHAT_PAY_BASE_URL` | 否 | 默认 `https://api.mch.weixin.qq.com` |
| `WECHAT_PAY_MCH_ID` | real 必填 | 微信支付商户号 |
| `WECHAT_PAY_APP_ID` | real 必填 | 小程序 AppID，需与商户号绑定 |
| `WECHAT_PAY_SERIAL_NO` | real 必填 | 商户 API 证书序列号 |
| `WECHAT_PAY_PRIVATE_KEY` | 二选一 | 商户 API 私钥 PEM 内联（生产建议 KMS/密钥管理） |
| `WECHAT_PAY_PRIVATE_KEY_PATH` | 二选一 | 商户 API 私钥只读文件路径（推荐生产） |
| `WECHAT_PAY_API_V3_KEY` | real 必填 | APIv3 密钥，固定 32 字节，用于解密回调 |
| `WECHAT_PAY_NOTIFY_URL` | real 必填 | 支付回调 HTTPS 地址 |
| `WECHAT_PAY_REFUND_NOTIFY_URL` | real 必填 | 退款回调 HTTPS 地址 |
| `WECHAT_PAY_PUBLIC_KEY_ID` | 二选一 | 微信支付公钥 ID（公钥模式） |
| `WECHAT_PAY_PUBLIC_KEY` | 二选一 | 微信支付公钥 PEM 内联值（公钥模式） |
| `WECHAT_PAY_PUBLIC_KEY_PATH` | 二选一 | 微信支付公钥只读文件路径（公钥模式，推荐生产） |
| `WECHAT_PAY_TIMEOUT_SECONDS` | 否 | 微信 API 请求超时，默认 10 秒 |
| `WECHAT_PAY_MAX_CLOCK_SKEW_SECONDS` | 否 | 回调时间戳容差，默认 300 秒 |
| `WECHAT_PAYMENT_MODE` | 旧链路 | 旧测试支付/旧回调模式，仅 development/testing 可用 |

> `real` 模式启动时会校验商户号、AppID、证书序列号、私钥、32 字节 APIv3 密钥和回调地址；缺任一项直接启动失败。
> 公钥模式与平台证书模式二选一：配置 `WECHAT_PAY_PUBLIC_KEY_ID/PUBLIC_KEY` 后不再下载平台证书。

敏感信息填写位置：

- `WECHAT_PAY_PRIVATE_KEY` 或 `WECHAT_PAY_PRIVATE_KEY_PATH`
- `WECHAT_PAY_API_V3_KEY`
- `WECHAT_PAY_PUBLIC_KEY`

**生产环境请使用 KMS 或加密配置，切勿提交真实密钥。**

## 三、用户端预支付

### `POST /api/v1/payments/orders/{order_no}/prepay`

**用途**：为当前用户待支付订单创建微信 JSAPI 预支付单。
**Method**：`POST`
**是否需要登录**：是
**请求体**：无
**成功状态码**：200
**失败**：404 订单不存在；409 状态/过期/渠道/OpenID 不符；503 网关未启用或微信异常。

路径参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `order_no` | string(8-64) | 当前用户创建、状态 0、未过期、`channel=wechat` 的订单号 |

成功响应：

```json
{
  "app_id": "wx1234567890",
  "time_stamp": "1761800000",
  "nonce_str": "9f2c1d3e4a5b6c7d",
  "package": "prepay_id=wx301234567890abcdef",
  "sign_type": "RSA",
  "pay_sign": "base64-rsa-signature"
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `app_id` | string | 前端映射为 `appId` |
| `time_stamp` | string | 秒级时间戳，前端映射为 `timeStamp` |
| `nonce_str` | string | 随机串，前端映射为 `nonceStr` |
| `package` | string | `prepay_id=...` |
| `sign_type` | string | 固定 `RSA` |
| `pay_sign` | string | RSA 签名，前端映射为 `paySign` |

业务规则：

1. 前端先创建业务订单，再调用本接口；
2. 用户必须已有 `users.openid`，否则 409 `WECHAT_OPENID_REQUIRED`；
3. 支付结果以服务端回调为准，前端 `wx.requestPayment` 的 `success` 只用于刷新页面；
4. 重复调用复用同一 `out_trade_no`，不要由前端生成订单号；
5. `WECHAT_PAY_MODE != real` 时返回 503。

## 四、支付回调

### `POST /api/v1/payments/wechat/notify`

**用途**：接收微信支付 APIv3 支付通知。
**Method**：`POST`
**认证**：微信平台证书/公钥验签
**请求体**：微信原始 JSON（服务端先读原始字节）
**成功状态码**：204（无响应体）

请求头：

| Header | 必填 | 说明 |
|---|---|---|
| `Wechatpay-Timestamp` | 是 | 秒级时间戳，超出容差拒绝 |
| `Wechatpay-Nonce` | 是 | 随机串 |
| `Wechatpay-Signature` | 是 | 平台证书/公钥签名 |
| `Wechatpay-Serial` | 是 | 平台证书序列号或公钥 ID |

处理规则：

1. 验签：`timestamp\nnonce\nbody\n`；
2. 校验时间戳在 `WECHAT_PAY_MAX_CLOCK_SKEW_SECONDS` 内；
3. 用 APIv3 密钥解密 `resource`；
4. 以 `notify_id` 写入 `payment_notify_log`，唯一键防重放；
5. `event_type=TRANSACTION.SUCCESS` 时校验：
   - `mchid` 与配置一致
   - `appid` 与配置一致
   - `trade_state=SUCCESS`
   - `amount.total` 与订单金额（分）一致
   - `currency=CNY`
   - `transaction_id` 未被其他订单占用
6. 更新 `payment_order` 为已支付，并同事务写入 `payment_fulfillment_job`；
7. 已支付订单重复通知幂等返回 204。

错误响应：

| HTTP | 场景 | 响应体 |
|---:|---|---|
| 401 | 签名失败、时间戳过期、解密失败 | `{"code":"FAIL","message":"签名验证失败"}` |
| 409 | 金额/商户号/AppID/状态/订单校验失败 | `{"code":"FAIL","message":"..."}` |
| 204 | 成功或重复通知 | 无 |

## 五、后台退款

### `POST /api/v1/admin/finance/orders/{order_id}/refunds`

**用途**：后台发起真实微信退款。
**Method**：`POST`
**权限**：后台 `finance.write`
**敏感操作**：`Idempotency-Key` + `confirm=true`
**成功状态码**：201

请求体：

```json
{"amount": 68.00, "reason": "用户申请退款"}
```

返回：

```json
{
  "refund_no": "RF20261030120000ABCD1234",
  "order_no": "VIP20261030115900ABCDE",
  "amount": 68.00,
  "refund_type": "PARTIAL",
  "status": "PROCESSING",
  "wechat_refund_id": "503000000020261030000000000001"
}
```

规则：

1. 锁订单行（`FOR UPDATE`）；
2. 只有 `status=1`、`channel=wechat`、未全额退款可退；
3. 可退余额 = 订单金额 − `CREATED/PROCESSING/SUCCESS` 退款合计；
4. 先写 `payment_refund(CREATED)` 并 commit，再调微信；
5. 微信超时/5xx：保留 `CREATED`，设置 `next_retry_at`，由 Worker 查询补偿；
6. 微信明确 4xx：置 `FAILED` 并告警；
7. 退款成功后更新订单累计退款金额：
   - 部分退款：`status=1`、`refund_status=PARTIAL`
   - 全额退款：`status=3`、`refund_status=FULL`
8. 仅全额退款投递一次 `REVOKE:{refund_no}` 到 `payment_fulfillment_job`；
9. 部分退款不立即回收全部权益。

错误：`409` 状态/金额/渠道不符；`502` 微信退款失败；`503` 支付网关未启用。

## 六、退款回调

### `POST /api/v1/payments/wechat/refund-notify`

**用途**：接收微信退款 APIv3 通知。
**Method**：`POST`
**认证**：平台证书/公钥验签
**成功状态码**：204

规则：

1. 与支付回调相同的验签、解密、`notify_id` 防重放；
2. 按 `out_refund_no` 锁退款单；
3. 校验通知金额与退款单金额；
4. 更新 `payment_refund.status/notify_id/success_time/fail_reason`；
5. 退款成功时更新订单累计退款金额与状态；
6. 仅订单全额退完时投递 `REVOKE:{refund_no}`。

微信退款状态映射：

| 微信 | 本地 |
|---|---|
| `SUCCESS` | `SUCCESS` |
| `PROCESSING` | `PROCESSING` |
| `CLOSED` | `CLOSED` |
| `ABNORMAL` | `FAILED` |

## 七、后台代用户创建会员订单

### `POST /api/v1/finance/orders`

**用途**：后台代用户创建会员订单；价格只从套餐配置读取。
**Method**：`POST`
**权限**：后台 `finance.write`
**请求头**：`Idempotency-Key`（8-128）

请求体：

```json
{"user_id": 123, "package_code": "monthly"}
```

说明：

- 不接受 `amount/product_name`；
- 服务端从 `config_membership_package` 读取价格与名称；
- 同 `user_id + type=1 + idempotency_key` 幂等回放。

其他商品类型使用各自专用接口：爆灯、置顶、红娘服务单、活动、虚拟商品。

## 八、Worker 部署与运行

### 8.1 履约/退款补偿 Worker

文件：`app/workers/payment_worker.py`

职责：

- 消费 `payment_fulfillment_job`（FULFILL/REVOKE）；
- 每 60 秒补偿查询 `payment_refund` 中 `CREATED/PROCESSING` 且到期的退款；
- 退款查询最多 8 次，失败/CLOSED/仍处理中达到上限 → 本地 `FAILED` 并输出 `payment_refund_dead`；
- 单任务失败不影响其他任务。

运行：

```bash
python -m app.workers.payment_worker --once
python -m app.workers.payment_worker --interval 5
python -m app.workers.payment_worker --once --limit 50
python -m app.workers.payment_worker --dry-run
```

systemd 示例：

```ini
[Unit]
Description=Xuanshiai Payment Worker
After=network.target mysql.service

[Service]
Type=simple
WorkingDirectory=/home/xuanshiai
EnvironmentFile=/home/xuanshiai/.env
ExecStart=/home/xuanshiai/.venv/bin/python -m app.workers.payment_worker --interval 5
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 8.2 对账 Worker

文件：`app/workers/reconcile_worker.py`

职责：

- 调 `/v3/bill/tradebill` 获取交易账单；
- 解压/解码 CSV；
- 写 `payment_reconcile_batch`；
- 与 `payment_order/payment_refund` 比对；
- 差异写 `payment_reconcile_diff`。

运行：

```bash
python -m app.workers.reconcile_worker --once
python -m app.workers.reconcile_worker --once --bill-date 2026-10-29
python -m app.workers.reconcile_worker --interval 86400
```

> 微信账单日期按 UTC+8；默认核对商户本地昨日。建议用 systemd timer 每天调用 `--once`。

## 九、对账与差错

对账批次：`payment_reconcile_batch`
差异类型：

- `LOCAL_ONLY`：本地有、微信无
- `REMOTE_ONLY`：微信有、本地无
- `AMOUNT_MISMATCH`：订单金额不一致
- `STATUS_MISMATCH`：订单状态不一致
- `REFUND_MISMATCH`：退款单缺失/金额不一致

差异处理：

- `payment_reconcile_diff.resolution`：`OPEN/IGNORED/RESOLVED`
- 处理人、处理时间、备注均落表；
- 差异 > 0 建议接入告警。

## 十、错误码总表

| HTTP | 含义 | 前端/调用方处理 |
|---:|---|---|
| 401 | 未登录、签名/解密失败 | 重新登录或拒绝回调 |
| 404 | 订单/退款单不存在 | 刷新订单 |
| 409 | 状态、金额、渠道、幂等冲突 | 展示业务提示，不重试相同请求 |
| 422 | 参数/幂等键格式错误 | 修正参数 |
| 428 | 敏感操作缺少 `confirm=true` | 二次确认 |
| 502 | 微信 API 失败 | 可重试，检查微信侧状态 |
| 503 | 网关未启用/配置缺失 | 检查 `WECHAT_PAY_*` 配置 |
